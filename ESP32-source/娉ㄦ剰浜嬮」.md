# 注意事项

用于记录项目中已经遇到并解决过的问题，方便后续排查时直接复用结论。

## 记录规则

- 每次出现问题并确认解决后，追加一条记录。
- 记录至少包含：日期、现象、原因、解决方案、结果。
- 如果问题和硬件接线、串口、烧录、网络或参数配置有关，尽量写清具体端口、通道号或命令。

## 问题记录

### 2026-05-13 当前运动调试范围

- 现象：Web 中存在 `OTTO 仿真` 和 `3D 工作台` 页面，但当前实体机器人调试阶段暂时不用这两个区域。
- 原因：目前调参重点是实体机器人通过 Web 按钮、后端、ESP32 固件和 PCA9685 舵机驱动形成的真实控制链路；仿真和 3D 工作台结果不作为当前运动效果判断依据。
- 处理约定：后续调整 Otto 运动逻辑、稳定区/激进区参数、舵机通道、PCA9685 状态和 Wi-Fi OTA 时，不主动修改或依赖 `OTTO 仿真`、`3D 工作台` 两个区域。
- 结果：当前应优先检查 `实时控制区(Otto)`、稳定区/激进区按钮 payload、后端 `/api/control`、ESP32 `/status` 和固件 Otto 步态逻辑。

### 2026-04-27 重新烧录 `esp32_robot_controller` 时上传中断

- 现象：首次上传时串口提示 `Could not open /dev/cu.usbserial-0001`，提升权限后再次上传又出现 `The chip stopped responding`。
- 原因：第一次是串口访问权限受限；第二次已经连上板子，但在写入早期阶段板子短暂失去响应，属于烧录过程中的通信不稳定。
- 解决方案：保留已编译固件不变，继续使用 `/dev/cu.usbserial-0001` 重试上传；第二次重试后完整写入 bootloader、分区表和主固件，并通过校验。
- 结果：烧录成功，设备已自动复位，新舵机通道映射已写入固件。

### 2026-04-27 单舵机测试后机器人连接自动断开

- 现象：在舵机调节区测试单个舵机后，机器人 websocket 连接自动断开，需要重新连接。
- 原因：固件里的 `SERVO_INVERTED` 配置与注释不一致，右侧三关节本应反向，但实际把 `左胯qh` 设成了反向、`右胯qh` 没反向，容易导致某一路测试时方向错误、机械顶死或电流突增；同时服务端原先在掉线后不会自动重连。
- 解决方案：将 `SERVO_INVERTED` 修正为右膝、右胯zy、右胯qh 反向；前端手动滑块限制到固件角度范围；服务端新增掉线自动重连逻辑并已重启生效。
- 结果：代码侧修正已完成，服务端已生效；固件部分还需要在主控重新接上 USB 串口后再重烧一次才能完全生效。

### 2026-04-27 Web “一键归中” 与装配时的归中基准不一致

- 现象：点击 Web 里的“一键归中”后，部分舵机会歪；但装配舵机时，曾用独立测试程序把 PCA9685 输出到物理 90 度后再安装舵盘。
- 原因：Web 原来的“一键归中”实际走的是“按已保存零位偏移归中”，不是“回到物理 90 度”；如果之前保存过零位偏移，姿态就会和装配时的基准不一致。
- 解决方案：将按钮语义改清楚。“按零位归中”保留原行为；另一个按钮改为“清零偏移并归中”，执行清空全部零位偏移后再统一回到物理 90 度，这与装配时的归中程序一致。
- 结果：前端逻辑和文案已修正，后续如果要回到装配时的机械中位，应使用“清零偏移并归中”。

### 2026-04-27 回到装配归中后左右腿偏差仍不一致

- 现象：点击“回到装配归中（物理90°）”后，两条腿偏的角度不一样，不是简单的整体一起偏。
- 原因：这是“全局中点基准”和“每个舵机自己的机械零位”叠加后的结果。全局上，当前固件原先的脉宽范围与装配时测试程序不一致；个体上，不同舵机的舵盘齿位、安装角度和左右镜像会带来不同的零位误差。
- 解决方案：把固件脉宽范围改为与装配程序一致的基准（对应 `SERVOMIN=110`、`SERVOMAX=510`）；同时在 Web 中新增“把当前姿态设为零位”，用于在分别调好各舵机后一次性保存新的零位。
- 结果：代码已修正并通过构建；固件改动需要重新刷入主控后生效。

### 2026-04-27 左右胯 qh 单舵机控制前后方向相反

- 现象：在舵机控制区单独调 `左胯qh`、`右胯qh` 时，期望往前却实际往后，两个 `qh` 的前后逻辑都反了。
- 原因：这两路在固件 `SERVO_INVERTED` 中的反向配置与当前机械安装方向不匹配。
- 解决方案：将 `SERVO_INVERTED` 中 `左胯qh`、`右胯qh` 的反向位切回当前机械结构对应的方向配置。
- 结果：固件代码已修正并编译通过，重新刷入主控后生效。

### 2026-04-28 PCA9685 运行中掉线后长期保持未就绪

- 现象：机器人在线，但 Web 显示 `PCA9685 未识别` / `PCA9685 not ready`，且 `servoWriteFailures` 持续暴涨。
- 原因：旧固件只在启动时探测一次 PCA9685；一旦运行中写失败，就把 `servoDriverReady` 置为 `false`，之后不会自动重试恢复。
- 解决方案：新增 PCA9685 自愈逻辑。驱动未就绪时按固定间隔自动重探测；重连成功后自动恢复当前保存的舵机姿态；同时取消“未就绪时每次控制都累加失败计数”的行为。
- 结果：固件代码已修正并编译通过，刷入主控后生效。
