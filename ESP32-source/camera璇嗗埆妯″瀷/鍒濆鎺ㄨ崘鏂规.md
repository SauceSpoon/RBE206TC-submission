# 推荐方案（最适合你这个比赛）

## 识别拆成两步

**第一步：颜色识别（HSV阈值分割）**
**第二步：形状识别（小型分类器，只分4类形状）**

**最终类别 = 颜色ID + 形状ID（共12类）**

## 为什么这样更稳

- 颜色分割在ESP32上计算便宜、速度快
- 形状模型只做4分类，模型更小、泛化更好
- 现场抽签只需切换目标ID，不用重训模型

## 机器人执行逻辑

1. 抽签后得到目标（例如 红色+圆柱）
2. 视觉扫描场地，找出所有候选目标
3. 匹配目标类别后，选最近目标靠近
4. 居中对齐后前进触碰
5. 连续2-3帧确认同一目标再触碰，避免误碰

## 你可以直接照着做的实施步骤

### 硬件与底盘

- **主控：** ESP32-CAM（最好带PSRAM）
- 建议加一个测距（VL53L0X或超声）用于最后接近，视觉只负责"看见+对齐"
- 电机驱动和底盘正常循迹/差速控制

### 数据采集（决定成败）

- 每个"颜色+形状"至少300张，12类共至少3600张
- 每类都要覆盖：正放、斜放、侧放、部分遮挡、远近变化
- 再采"负样本"2000张（背景、非目标、手、杂物）
- 现场光照条件尽量提前采一批

### 训练策略

- **颜色：** 手工HSV阈值，不用训练
- **形状：** 对ROI裁剪后训练4分类小模型（建议64x64灰度输入，int8量化）
- 平台可用Edge Impulse导出Arduino库
- 目标性能：单帧推理 < 150ms，整机2~5 FPS可用

### 在线流程（每帧）

1. 获取图像
2. 转HSV，按4种颜色阈值找连通域
3. 对每个候选区域裁剪ROI
4. ROI送入"4形状分类器"
5. 得到类别和置信度
6. 若类别=抽签目标且置信度>阈值（如0.75），加入目标跟踪队列

### 控制策略（触碰）

- 用目标框中心点x与图像中心做误差
- 误差大：原地微调转向
- 误差小：前进
- 距离<阈值或碰撞开关触发：停止，判定成功
- 若目标丢失：后退一点并重新扫描

## 现场容易翻车的点和规避

### 光照变化导致颜色漂移

- 比赛前做一次HSV快速校准
- 锁定白平衡/曝光（不要自动来回跳）

### 误识别

- 必须"连续多帧一致"才执行触碰
- 置信度阈值分两级：检测阈值0.6，执行阈值0.75

### 算力不足

- 降分辨率到QQVGA/QVGA
- 模型输入降到64x64
- 只在检测到候选色块时才跑形状模型

### 抓错目标

- 执行前最后一次近距离复核（停一下再识别1帧）
